Vehicle Insurance Claim Fraud Risk Classification System

A machine-learning decision-support project that ranks vehicle insurance claims by estimated fraud risk, helping investigators prioritise which claims to review first.

View source on GitHub ↗Explore model results
Responsible-use note: ClaimGuard is a review-prioritisation aid, not an automated fraud decision-maker. A high score is not proof of fraud. Every flagged claim requires human review.

Project overview

The project follows an end-to-end workflow: exploratory analysis, leakage-aware feature preparation, model training, evaluation and a desktop interface for single-claim and batch assessment.

Data leakage discovery

fraud_risk_score perfectly separated the target classes. It was excluded because it would reveal the answer rather than provide a legitimate signal available at initial claim assessment. Post-decision fields, investigation-stage fields, identifiers and personal names were also excluded from model inputs.

Methodology

The pipeline was designed to reduce leakage and produce a more realistic estimate of performance on unseen customers.

Data preparation

Remove leakage-prone fields and derive five date features: claim month, day of week, reporting delay, policy tenure and vehicle age at claim.

Customer-aware split

Use StratifiedGroupKFold with customer_id as the grouping variable: 80,000 training records and 20,000 test records, with no customer overlap.

Preprocessing

Median imputation for numerical columns; most-frequent imputation and one-hot encoding for categorical columns. Fit transformations on training data only.

Class imbalance

Apply SMOTE inside the training pipeline so validation and test data remain untouched.

Model training

Compare Logistic Regression with a Grid-Search-tuned Random Forest.

Threshold and evaluation

Select the threshold on a validation split, then evaluate once on the held-out test set.

Model performance

The tuned Random Forest achieved better ranking metrics than the Logistic Regression baseline. Selecting a lower validation-based threshold improved fraud recall.

Limitations & future work

Current results are moderate and come from one public dataset. Before real-world use, the system needs external validation, fairness checks, probability calibration and monitoring.

Explainability

Add claim-level explanations, for example with SHAP.

Better imbalance handling

Evaluate SMOTENC or class weighting to preserve categorical structure.

Responsible deployment

Assess fairness, drift, privacy, calibration and performance on independent insurer data.
